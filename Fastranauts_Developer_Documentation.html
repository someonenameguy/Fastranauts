1. Ostranauts Engine Primer: Domain Model & Simulation Loop

Before diving into Fastranauts's patches, a new engineer needs to understand how Ostranauts (Assembly-CSharp.dll) is architected. Unlike typical Unity games that rely on GameObject components for everything, Ostranauts is a hybrid data-driven simulation built around the following core classes:

CondOwner (CO)Core Entity

The universal simulation object. Every ship tile, wall, door, gas canister, reactor, human crew member, wound, and room has a CondOwner. It holds a dictionary of active conditions (mapConds), key-value UI stats (mapInfo), interaction cooldowns (dictRecentlyTried), and a reference to its visual Item and parent Ship.

Condition & CondTrigger (CT)Rule Engine

Condition represents a state or numeric property on a CondOwner (e.g., StatDamage, StatGasMolO2, IsRoom). CondTrigger is a boolean predicate defined in JSON that tests if a CondOwner satisfies a set of conditions. Gotcha: Calling DataHandler.GetCondTrigger(name) clones a brand-new CondTrigger on the heap by default!

CrewSim & aTickersMaster Loop

CrewSim is the central singleton driving gameplay. It maintains CrewSim.aTickers (a UniqueList<CondOwner>) containing every CondOwner that needs periodic rule/timer updates. In CrewSim.Update(), it advances simulation time and calls UpdateICOs() to tick items.

StarSystem & fEpochSim Clock

StarSystem.fEpoch is a double representing absolute elapsed simulation time in seconds. Many simulation MonoBehaviour components (GasPump, BodyTemp, Heater, FusionIC, Sensor) compute their delta time in Update() as double dt = StarSystem.fEpoch - this.fLastUpdate;.

Ship, Room & GasContainerSpatial Grid

Each spacecraft or station is a Ship containing a dictionary of mapped objects (GetMappedCos()), a list of enclosed Rooms (aRooms), and docked ships (mapDocked). GasContainer manages partial pressures, temperature, and moles of gases for both rooms and canisters.

Item & PDAVisualisersRendering

Item is the Unity MonoBehaviour attached to physical ship objects. It manages sprites, lights, and shader property blocks (MaterialPropertyBlock _mpb). PDAVisualisers drives the player's PDA status overlays (Power, Heat, Pressure, O2, Damage) by sweeping all ship Items.

🧠 Key Architectural Insight: The Two Competing Update Systems in Vanilla Ostranauts

Ostranauts has two separate update mechanisms running concurrently on the Unity main thread:
1. The Sub-Stepped Ticker Loop (CrewSim.Update → AdvanceSim → UpdateICOs): Advances StarSystem.fEpoch in small increments and calls CondOwner.UpdateManual(10).
2. Unity's Per-Frame MonoBehaviour.Update() & FixedUpdate(): Hundreds of components (GasContainer, GasPressureSense, GasPump, BodyTemp, PDAVisualisers, GUIOutput, etc.) run in standard Unity Update() every rendered frame, either accumulating Time.deltaTime or comparing StarSystem.fEpoch - fLastUpdate.
Understanding how these two systems interact with Time.timeScale and CrewSim.Paused is the foundation of Modules 1, 2, and 3!

3. The 5 Non-Negotiable Engineering Mandates

When reviewing or writing code in Fastranauts, you must adhere to these five architectural rules:

Mandate 1: Zero Managed Allocations in Hot Paths (0 Bytes GC)

Unity's Mono runtime uses the non-compacting, stop-the-world Boehm-Demers-Weiser garbage collector. Allocating temporary List<T>, arrays, LINQ iterators, boxed structs, or substrings inside Update() or LateUpdate() eventually forces a full heap scan pause. Always use pre-sized static collections, clear them before use (.Clear()), and watch out for hidden allocations like Dictionary.Keys enumerators or struct keys without custom IEqualityComparer<T>.

Mandate 2: Prefer Surgical CIL Transpilers Over Destructive Prefixes

Writing a Harmony Prefix that returns false skips the original method body—which also breaks any other mod whose patch relies on that method executing, or requires you to copy-paste hundreds of lines of vanilla code. Whenever possible, use a Harmony Transpiler to swap out only the specific offending instruction (e.g., replacing newobj List<CondOwner>::.ctor() with call GetClearedDoorSensorList()).

Mandate 3: Re-Entrancy Safety for Shared Static Buffers

Since Unity scripts run on a single main thread, static buffers do not need multi-threaded locks—but they DO need re-entrancy analysis! Never share a single static List<CondOwner> between a caller method and a callee method. For example, in SensorAndDoorOptimizationModule, GasPump.Respire2() calls GetA() and GetB() while iterating its own list, so we maintain 4 distinct static buffers (_sharedDoorSensorList, _sharedPumpListA, _sharedPumpListB, _sharedRespireList).

Mandate 4: Strict Simulation & Save-File Invariance

Fastranauts is a pure performance optimizer. It must never alter gameplay balance, atmosphere physics math, reactor fuel consumption, or save file formats. When throttling epoch-based components at 2x–16x speed, always ensure the component still computes its exact elapsed simulation time via StarSystem.fEpoch - fLastUpdate, and respect internal simulation clamps (such as FusionIC's 1.0-second delta clamp).

Mandate 5: Fault Isolation & Live Telemetry Verification

Every patch registration must be guarded so a game update changing one method signature never crashes the plugin. Every optimization must increment a counter in FastStats so its effectiveness can be verified live in-game via F8 or the fastinfo console command.

4.4 FastRaycast.cs — Zero-Allocation Raycast & LINQ Replacement Engine

In vanilla Ostranauts, three ultra-hot methods (Ship.GetCOsAtWorldCoords1, CrewSim.GetMouseOverCO, and CrewSim.GetMouseOverBG) execute variations of this pattern every frame:

Vanilla Raycast + LINQ Pattern (3 Heap Allocations Per Call) 
// 1. Physics.RaycastAll allocates a new RaycastHit[] array on the managed heap
RaycastHit[] array = Physics.RaycastAll(ray, 100f, mask);

// 2. Enumerable.OrderBy allocates an OrderedEnumerable<RaycastHit, float> + Buffer<RaycastHit> + int[] map
IOrderedEnumerable<RaycastHit> ordered = array.OrderBy((RaycastHit go) => go.distance);

// 3. Either iterated via foreach (allocating an IEnumerator) OR converted via .ToArray() (allocating another RaycastHit[])

Why Naive Physics.RaycastNonAlloc Fails Without _arraysByLength

A naive developer might try replacing Physics.RaycastAll with a single RaycastHit[64] scratch buffer and returning that 64-element buffer directly. That would break the game! Why? Because the caller in vanilla code iterates for (int i = 0; i < array.Length; i++)! If you return a 64-element array when only 3 colliders were hit, elements [3..63] contain stale or null colliders from previous frames!

How FastRaycast Solves This With 0 Bytes Allocated:

  1. Pre-Allocated Size Lookup Table (_arraysByLength[0..64]): In the static constructor, FastRaycast allocates 65 arrays once at startup: an array of length 0, an array of length 1, ..., up to length 64.
  2. Scratch Buffer + In-Place Insertion Sort: Physics.RaycastNonAlloc(ray, _scratchBuffer, ...) writes hits into _scratchBuffer and returns the exact hit count count. Because count in a 2D ship slice is tiny (typically 1 to 12 hits, capped at 64), an in-place insertion sort sorts _scratchBuffer[0..count-1] by distance in nanoseconds with zero allocations.
  3. Exact-Length Array Return: It copies the count sorted hits into _arraysByLength[count] and returns it. The caller sees an array whose .Length is exclusively equal to count, already sorted by distance!
  4. Zero-Alloc LINQ Pass-Through (ZeroAllocOrderedHitEnumerable): When vanilla IL subsequently calls Enumerable.OrderBy(hits, go => go.distance), our transpiler redirects that call to FastRaycast.PassThroughOrderBy, which wraps the already-sorted array in a singleton SharedOrderedEnumerable implementing both IOrderedEnumerable<RaycastHit> and IEnumerator<RaycastHit>. If vanilla IL then calls .ToArray(), FastRaycast.ToArrayZeroAlloc simply unwraps and returns SharedOrderedEnumerable.BackingArray!
src/Common/FastRaycast.cs — Complete Implementation 
public static class FastRaycast
{
    public const int MaxHits = 64;
    private static readonly RaycastHit[] _scratchBuffer = new RaycastHit[MaxHits];
    private static readonly RaycastHit[][] _arraysByLength = new RaycastHit[MaxHits + 1][];
    public static readonly ZeroAllocOrderedHitEnumerable SharedOrderedEnumerable = new ZeroAllocOrderedHitEnumerable();

    static FastRaycast()
    {
        for (int i = 0; i <= MaxHits; i++)
            _arraysByLength[i] = new RaycastHit[i];
    }

    private static RaycastHit[] FinalizeHits(int count)
    {
        if (count <= 0)
        {
            SharedOrderedEnumerable.SetData(_arraysByLength[0], 0);
            return _arraysByLength[0];
        }
        if (count > MaxHits) count = MaxHits;

        // In-place insertion sort by distance (0 allocations, optimal for small N <= 64)
        for (int i = 1; i < count; i++)
        {
            RaycastHit key = _scratchBuffer[i];
            float keyDist = key.distance;
            int j = i - 1;
            while (j >= 0 && _scratchBuffer[j].distance > keyDist)
            {
                _scratchBuffer[j + 1] = _scratchBuffer[j];
                j--;
            }
            _scratchBuffer[j + 1] = key;
        }

        RaycastHit[] result = _arraysByLength[count];
        Array.Copy(_scratchBuffer, 0, result, 0, count);
        SharedOrderedEnumerable.SetData(result, count);
        return result;
    }

    public static IOrderedEnumerable<RaycastHit> PassThroughOrderBy(
        IEnumerable<RaycastHit> source, Func<RaycastHit, float> keySelector)
    {
        if (source is RaycastHit[] arr)
        {
            SharedOrderedEnumerable.SetData(arr, arr.Length);
            return SharedOrderedEnumerable;
        }
        return Enumerable.OrderBy(source, keySelector);
    }

    public static RaycastHit[] ToArrayZeroAlloc(IEnumerable<RaycastHit> source)
    {
        if (ReferenceEquals(source, SharedOrderedEnumerable)) return SharedOrderedEnumerable.BackingArray;
        if (source is RaycastHit[] arr) return arr;
        return Enumerable.ToArray(source);
    }
}

2. Root-Cause Code Trace: The 4 Compounding Vanilla Bugs

  1. The force = true Dirty-Check Bypass Bug: In Item.VisualizeOverlays(bool force) (Item.cs:169), the original developers wrote a smart epsilon check: if (!force && Math.Abs(this._fOverlayAmount - this._fShaderOverlayLastFrame) < 0.001 && this._vShaderOffsetLastFrame == this._vShaderOffset) return; However, in PDAVisualisers.NotifyShips(), they hardcoded allLoadedShips[i].VisualizeOverlays(true);! Because force was unconditionally true, the dirty check was never used. Every 0.5 seconds, all 4,000–8,000 items on loaded ships evaluated triggers, queried spatial rooms, and called Unity's native rend.GetPropertyBlock(_mpb) and rend.SetPropertyBlock(_mpb) even when 99.8% of items hadn't changed!
  2. The 16x TimeScale & Pause Bug: PDAVisualisers.Update() accumulated this._pingTime += Time.deltaTime;. Because Ostranauts leaves Time.timeScale = 16f even when CrewSim.Paused == true, _pingTime > 0.5f fired 32 times per real second (almost every frame!) at 16x speed, even while the game was paused!
  3. 211 KB Heap Allocation per Sweep in Ship.VisualizeOverlays: Calling DataHandler.GetCondTrigger("Blank") cloned a new CondTrigger. Calling this.GetCOs(condTrigger, true, false, true) allocated a CondOwnerVisitorAddToHashSet (with a new HashSet<CondOwner>), wrapped it in a new CondOwnerVisitorCondTrigger, copied the HashSet to a CondOwner[] array, and built a new List<CondOwner>.

8. Harmony CIL Transpiler Engineering Handbook

Because 25 of Fastranauts's patches are Harmony CIL Transpilers, mastering them is the single most valuable skill for working on this codebase. Here are the 4 patterns used throughout Fastranauts and the golden rules you must follow.

Pattern 1: Single-Instruction Call / Constructor Swap (1-to-1)

When replacing a static method call, a property getter (like Time.get_deltaTime), or a parameterless constructor (like newobj List<CondOwner>::.ctor()) with a static helper that has the exact same stack input and output signature:

Pattern 1: 1-to-1 Instruction Swap (Preserving Labels!) 
ConstructorInfo listCtor = AccessTools.Constructor(typeof(List<CondOwner>), Type.EmptyTypes);
MethodInfo helperMethod = AccessTools.Method(typeof(SensorAndDoorOptimizationModule), nameof(GetClearedDoorSensorList));

foreach (CodeInstruction inst in instructions)
{
    // Stack before newobj: [...] -> Stack after newobj: [..., List<CondOwner>]
    // Stack before call:   [...] -> Stack after call:   [..., List<CondOwner>] (100% Stack Balanced!)
    if (listCtor != null && helperMethod != null && inst.opcode == OpCodes.Newobj && Equals(inst.operand, listCtor))
    {
        yield return new CodeInstruction(OpCodes.Call, helperMethod).WithLabels(inst.labels);
        continue;
    }
    yield return inst;
}

Pattern 2: Instance Call to Static Helper (Consuming this from the Stack)

In CIL, an instance method call like ship.GetCOs(condTrigger, bSub, bDocked, bLocked) pushes ship (this) onto the stack first, followed by the 4 arguments. That means a static replacement method with signature GetShipCOsForOverlayFast(Ship ship, CondTrigger ct, bool bSub, bool bDocked, bool bLocked) consumes the exact same 5 stack items in the exact same order! You can swap callvirt Ship::GetCOs(...) directly with call PdaOverlayOptimizationModule::GetShipCOsForOverlayFast(...)!

Pattern 3: 2-Instruction Peephole Window Replacement (2-to-1 + Nop)

When optimizing a 2-step sequence like list.ToArray() followed by mesh.set_vertices(array) (or dict.Keys followed by new List<string>(keys)), buffer the instructions into a List<CodeInstruction>, replace instruction i with your combined static call, and replace instruction i + 1 with new CodeInstruction(OpCodes.Nop).WithLabels(list[i + 1].labels) so any jump targeting i + 1 remains valid.

Pattern 4: Fast Private Field Access (FieldRefAccess & Open Delegates)

Never use FieldInfo.GetValue() or MethodInfo.Invoke() inside an Update() loop—reflection boxes value types and allocates parameter arrays! Instead, initialize compiled delegates once in Initialize():

  • For Private Fields: Use Harmony's AccessTools.FieldRefAccess<TInstance, TField>("fieldName"), which compiles a dynamic CIL getter/setter returning a ref TField with the exact speed of direct field access!
  • For Private Instance Methods: Use (Action<CondOwner>)Delegate.CreateDelegate(typeof(Action<CondOwner>), methodInfo) (an open-instance delegate), which invokes the private method at native function-pointer speed with 0 allocations.
